# Smile Weather · v0.4.1

[Live Demo · GitHub Pages](https://jeremyxu-design.github.io/smile-weather/) · [同源资源演示 · Sites](https://smile-weather-studio.xjylance.chatgpt.site/) · [Public Source](https://github.com/jeremyxu-design/smile-weather)

微笑下雨，大笑释放三波星星，移动头部让主层星星反弹。独立设计概念，非 TikTok 官方产品。纯前端，单 Canvas 2D，无服务端推理；应用不录制或上传摄像头画面，不请求麦克风。

## v0.4 变化

- 短暂丢脸不超过450ms时保留已确认表情，立即停雨并移除碰撞体；不会将缺失时间计入300ms确认窗口。长时间丢脸回到无脸状态。
- 雨滴撞头溅成水花后消失；主要星星保留物理反弹。
- 三档深度：背景粒子被头部椭圆遮住，中层参与碰撞，前层作为装饰。8颗大星星全部在中层。它是2.5D视觉近似，不是真实头部分割。
- 一次烟花按8颗大星、24颗中星、72颗小星与纸屑分三波释放，波间隔75ms；加入弹性出场、飞行拉伸与接触压缩，YAY在粒子之后绘制。
- 移除对Canvas roundRect的依赖，使用手绘圆角；这项降级检查不等于已验证iOS 15整条模型链路。
- 使用独立品牌，提高小字可读性，移动端下拉框16px；320px和390px窄屏布局已检查。

## 产品定义与验证

| 决策 | 实现 | 验证场景 |
| --- | --- | --- |
| 微笑持续下雨 | 双侧smile均值≥.40进入、≤.25退出，各稳定300ms | 阈值附近抖动不频繁切换 |
| 大笑优先 | smile≥.50且jawOpen≥.50；任一≤.35稳定300ms退出 | 仅张嘴不触发 |
| 一次笑一次烟花 | 进入大笑时触发，1.5s冷却；持有不连发，冷却不补发 | 持续5s；放松再笑 |
| 短暂丢脸容错 | 450ms以内保留已确认状态；碰撞和雨立即停；连续确认计时清零 | 大笑冷却后短暂丢脸再恢复，不额外释放 |
| 长时间失去人脸 | 距最后有效样本超过450ms重置状态，保留冷却 | 遮脸1s后恢复，需要重新确认表情 |
| 头部近似物理 | 轮廓在眼线局部坐标拟合旋转椭圆，顶部扩展15%；连续轨迹检测、法线反射和头部速度传递 | 歪头、镜像、横竖屏、迎向星星 |
| 模拟与识别分开 | 预览按钮、模拟丢脸只在预览出现；报告标记preview | 预览不得冒充摄像头验收 |

输入使用75ms时间常数平滑；300ms按单调时间计算。“大笑”是张嘴微笑的代理，不识别情绪或笑声。阈值尚需多人、不同光照校准。椭圆不能精确覆盖头发、大幅侧脸和遮挡。

## 性能预算与边界

- MediaPipe Tasks Vision固定0.10.35、float16/1模型、VIDEO模式、单脸、开启blendshapes。点击开启摄像头才加载模型；直接传video。
- 主线程同步推理，目标15Hz；保留调度相位并跳过错过的时隙，不追赶积压。真实Hz在面板测量，不保证每台设备都达到15Hz。GPU初始化失败尝试CPU；限频不消除单次阻塞，Worker为测量后的备选。
- rAF绘制上限60Hz；typed-array粒子池800/轻量400；水花32槽、碰撞闪星24槽复用。保留容量余量，未依据预览峰值擅自缩池。
- 粒子贴图与渐变启动时预绘；不逐粒子创建渐变，不用filter或shadowBlur。遮挡使用每帧一个椭圆合成；云朵、文字等有限辅助路径仍存在，不能声称所有帧零路径或零分配。
- 深度按三个固定桶绘制，无逐帧粒子排序；DPR上限1.5/轻量1。物理子步最大1/120s，单帧推进上限50ms。
- 页面隐藏暂停推理和渲染并禁用视频轨道；停止释放摄像头与模型。
- 导出JSON含浏览器、视频尺寸、配置、事件和性能摘要，不含图像或关键点。报告由测试者检查后分享，不提交公开仓库。诊断最多600个秒级样本、300个事件、450个滚动时间样本。

## Vibecoding复盘（不超过200字）

审查发现：持续大笑时，短暂丢脸会重置状态，冷却结束后恢复识别再次放烟花。我要求：“丢脸450ms内保留已确认状态，立即停雨和移除碰撞；缺失时间不得计入确认窗口。”合成序列修复前触发2次、修复后1次，新增丢脸与恢复回归测试。此结果来自合成测试，真机准确率另测。

## 运行与修改

`index.html`包含完整界面与业务代码，无构建步骤、无npm依赖。部署到HTTPS静态托管；本地电脑执行：

```sh
python3 -m http.server 4176 --bind 127.0.0.1
node --test core-tests.mjs
```

打开http://127.0.0.1:4176。手机用HTTPS演示链接。`core-tests.mjs`直接提取HTML核心实现，改代码后重新运行测试。GitHub Pages使用main分支根目录。

GitHub单文件版使用固定版本公共CDN，Sites版使用同源模型和脚本；业务代码相同，资源托管不同。首次摄像头需联网下载模型；无摄像头预览不加载模型。

## v0.4.1 · 大笑后的微笑重新确认

大笑确认退出时清除其继承的微笑状态，从该次有效样本起重新确认smile≥.40持续300ms，才开始下雨。不要求先回到平静；不足300ms的残留微笑不触发。已有烟花正常消散，冷却与丢脸容错不变。

300ms从“大笑状态确认退出”起算。原有大笑退出也需要300ms，另外存在输入平滑与采样延迟，因此不能宣称从实际闭嘴到下雨总共只有300ms。

新增3项回归测试，覆盖不同采样间隔、短暂残留/迟滞区间、丢脸打断重新确认和重新大笑优先级。模块版与单文件版各29项通过；新规则的真人体感仍需体验反馈。v0.4遮脸恢复用户反馈保留为历史证据。
