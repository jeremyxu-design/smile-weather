## 30秒体验

点击“开启摄像头” → 微笑 → 放松 → 张嘴大笑 → 左右动头。右上角工具可开启头部边界和碰撞点、切换画质、停止摄像头或导出运行记录。无摄像头时可以试模拟效果。

## 我如何定义这个玩法

我把“屏幕下雨”收敛为跟随主播的天气云，把烟花安排在头部上方或侧方：让表情与效果有明确联系，给雨滴水花和星星反弹留出轨迹，同时尽量为面部和评论留白。

| 行为 | 规则 |
| --- | --- |
| 微笑 | 双侧 smile 均值 ≥ .40 进入、≤ .25 退出，各持续300ms |
| 大笑 | smile ≥ .50 且 jawOpen ≥ .50；任一 ≤ .35 持续300ms退出，大笑优先 |
| 一次笑一次烟花 | 进入时释放、1.5秒冷却，保持大笑不连发 |
| 大笑转微笑 | 确认退出大笑后，重新确认微笑300ms |
| 短暂丢脸 | 450ms内保留已确认表情，立即停雨并移除碰撞体 |
| 物理互动 | 8颗大星及中层粒子碰到头部椭圆会反弹，雨滴碰到头顶溅开 |

v0.5.2 增加整段会话的平均渲染/识别频率与平均推理耗时；全程均值排除加载和后台间隔。原有表情规则、视觉效果和碰撞逻辑保持不变。

## 性能设计与成本

| 决策 | 当前实现 |
| --- | --- |
| 纯前端 | 无服务端逐帧推理调用费用；计算转移到用户设备。无 Three/Matter，贴图启动时预绘 |
| 控制绘制频率 | 实际绘制最高60Hz，主线程识别目标15Hz；后台暂停 |
| 复用内存 | 预分配800粒子槽，水花32槽、碰撞提示24槽 |
| 标准 / 轻量 | 活动预算800 / 400；画布DPR上限1.5 / 1；单簇均最多104颗 |
| 按需加载 | 点击开启摄像头后加载模型；模拟预览不加载模型 |

成本不等于零：仍有静态资源分发、首次加载等待、用户设备耗电与维护成本。

模型文件3,758,596字节；随运行环境选择的WASM约10.48–11.15MB（原始文件大小，非网络压缩传输量）。轻量模式降低像素绘制负担；保留池容量余量，后续用连续触发实测决定是否缩减。

## 验证结果

- **34项核心测试通过**：模块版与生成后的单文件版执行同一组测试，覆盖触发、丢脸恢复、连续碰撞、粒子复用及出生位置。
- v0.5.1 同场景模拟对照：只切换绘制限频，面板读数120.0 → 60.1 FPS；测量口径见QA。
- v0.5体验反馈：目前没有发现问题；早期iPhone核心流程及遮脸恢复也收到成功反馈。
- 2026-10-27，v0.5.2 MacBook Pro单人自测：微笑10/10、大笑8/10；讲话时微笑误触发1次；张嘴大笑前先出现雨2次。后者为表情过渡现象，尚无逐帧记录证明原因；两次大笑未命中仍待定位。
- 本轮来自v0.5.2 Sites验收请求下的用户反馈；系统、浏览器版本、光照、讲话试验总数及60秒性能日志未提供，不计算讲话误触发率。iPhone本轮数据待补。 详情见[验收表](https://github.com/jeremyxu-design/smile-weather/blob/main/ACCEPTANCE.md)。

**边界：** 模拟测试不等于摄像头实测；张嘴微笑是“大笑”的输入代理，头部物理是二维椭圆近似。300ms为状态确认窗口；识别主线程限频仍有单次阻塞。性能面板区分全程平均和约1秒窗口频率；P95为最近450样本，详细定义和历史证据见[QA](https://github.com/jeremyxu-design/smile-weather/blob/main/QA.md)。

## 决策说明

大笑优先，避免与微笑争抢反馈；持续大笑只释放一次，建立清晰动作奖励并限制计算量；短暂丢脸保留状态但移除碰撞体，避免重复发射和过期位置碰撞；大笑结束后重新确认微笑，过滤收嘴残留笑容。原型服务单人正面场景，未实现多人身份锁定。完整异常处理与升级条件见 DECISIONS.md。

## Vibecoding复盘（不超过200字）

初版把requestAnimationFrame当成固定60FPS，高刷屏模拟预览测得120.2FPS。我要求：“按单调时间将实际绘制限为60Hz，识别独立限15Hz；分别记录频率，模拟数据不得冒充摄像头性能。”改为到期才更新物理与绘制。同机同场景仅切换限频，模拟面板读数为120.0与60.1FPS，验证了绘制频率控制。

## 修改与运行

公开仓库包含可直接编辑的模块和生成脚本，Pages继续使用根目录 `index.html`。

| 文件 | 作用 |
| --- | --- |
| `app.mjs` / `dev.html` / `styles.css` | 生命周期、模块开发入口与界面 |
| `expression.mjs` / `geometry.mjs` | 表情状态机、坐标和连续碰撞 |
| `particles.mjs` / `metrics.mjs` / `config.mjs` | 粒子与渲染、统计、固定配置 |
| `modular-tests.mjs` / `core-tests.mjs` | 模块与生成单文件的同组回归测试 |
| `build.mjs` | 从模块生成 `index.html` 和单文件测试 |

```sh
npm run build
npm test
npm run serve
```

电脑打开 <http://127.0.0.1:4176/dev.html> 调试模块，修改后重新构建，再检查 `/index.html`。手机使用HTTPS。应用不录制或上传画面，不请求麦克风；直播评论为示例。

MediaPipe Tasks Vision固定0.10.35、float16/1模型。GitHub Pages与Sites均使用同域识别库、WASM和模型。[第三方资源与许可](https://github.com/jeremyxu-design/smile-weather/blob/main/THIRD_PARTY.md)。


## 2026-10-28 加载与兼容性修订

v0.5.3将识别库、WASM和模型随页面同域托管；微信、飞书、抖音/TikTok内置浏览器显示外部浏览器建议，仍允许尝试摄像头和模拟体验。复制失败时提供可手动复制的链接。目标网络冷启动与真人性能仍待测试，同域部署不代表大陆网络可达性已通过。

按预算情景估算：每次冷启动假设传输15MB，一万次约150GB（十进制）；假设流量单价为0.2元/GB，纯分发约30元。单价仅为敏感性演算，不是供应商报价或实际账单；缓存、压缩、托管配额与维护另计。本地推理免去服务端逐帧调用，但设备耗电、首用等待和兼容性由用户侧承担。
